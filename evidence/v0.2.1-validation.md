# Sprint Timer v0.2.1 validation checkpoint

Date: 2026-11-07

## Scope

Live detector integration:
- Original connected-component detection remains the acquisition path.
- Narrow recovery uses the last accepted position.
- Wider recovery follows narrow failure and is limited to one attempt per 200 ms.
- Existing match threshold remains 0.595 for these tests.
- Existing 300 ms timer confirmation logic is retained.
- Tracking proposals return from background work and are accepted on the UI thread.
- Existing generation checks reject results from before a session reset.
- Tracking clears on session resets and capture errors.
- Tracking is retained across ordinary confirmed icon absence.

No input-generation, game-memory access, or injection was added.
Focus guard, overlay, input handling, and settings assets were not patched.

## Known limitations and follow-up

- Initial pre-icon estimation does not explicitly log its start time.
- First icon confirmation does not log the retained estimate's elapsed value.
- Total first-run duration cannot be reconstructed from those logs.
- Earlier exploratory activity included near-threshold wider matches at
  scores 0.600 and 0.605; their visual correctness remains unverified.
- Broader false-positive coverage and live processing/sample-interval
  performance are not established by these logs.
- Offline replay does not execute the actual live timer state machine.
- No anti-cheat approval or ban-safety claim is made.

Next proposed change is diagnostic logging only, separate from detector tuning.

## Repository contents

Application source, build script, experiment source, and recorder scripts are
retained. Raw recordings, generated results, compiled executables, compiler
output, and copied experiment inputs are excluded.

Some experiment scripts depend on those local input snapshots and earlier
tool folders. Preserving their source does not make every historical experiment
independently runnable from a fresh clone.

Raw evidence remains local under capture-diagnostics; backup folders are
retained locally. This checkpoint does not delete them.
